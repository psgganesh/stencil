# Firebase support on each platform

Type: research
Status: resolved
Blocked by:

## Question

For `firebase_core`, `firebase_auth` and `cloud_firestore` (current FlutterFire), find out which of web, iOS, Android, macOS and Windows are supported, and with what limits. In particular:
- Windows: is it supported for production or only for development?
- Offline persistence on each platform.
- Google and Apple sign-in on each platform.

Then find out how the app can tell at startup that "the Firebase config is present" so it can switch from the fake repositories to Firestore. Consider `firebase_options.dart` generated by `flutterfire configure`, a missing `google-services.json` or `GoogleService-Info.plist`, and `--dart-define`. The check must not break the build when there's no config.

Also find out what FCM push notifications need on each platform (APNs keys are manual work).

## Answer

- Android, iOS and web fully support core, auth, Firestore and FCM. macOS is beta. Windows has core, auth and Firestore for **development only** (Firebase: "not intended for production"), and no FCM.
- Google sign-in works on Android, iOS, macOS and web. Apple sign-in works on iOS, macOS, Android and web. Neither works on Windows (`signInWithProvider` is unimplemented there, and neither plugin supports Windows).
- Offline persistence is on by default on Android and Apple platforms. On web it is opt-in (`enablePersistence`) and works only in Chrome, Safari and Firefox.
- FCM needs manual setup: an APNs `.p8` key upload plus Xcode capabilities for iOS and macOS, and a VAPID key plus `firebase-messaging-sw.js` for web.
- Config detection: commit a stub `lib/firebase_options.dart` in the CLI's shape (every platform throws `UnsupportedError`). In `main()`, try `currentPlatform` and `initializeApp(options:)`; if either fails, use the fakes. An optional `--dart-define=USE_FAKES` can force the fakes.
